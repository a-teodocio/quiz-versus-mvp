# Fidelity log

The mock must behave like the real quiz app. Each row records a deliberate difference, so a later port knows what was not exercised.

| Area                                 | Real app                                                                                                | Mock                                                                                                                                                                        | Why                                                                                      | Port risk                                                      |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Content                              | Real course notes and instructor images                                                                 | Fake notes, generated placeholder images                                                                                                                                    | Public repo                                                                              | None: schema is identical                                      |
| Typed answers that need self-grading | Answers with digits, commas or slashes are typed, shown, then marked by the student                     | Versus asks for typed text only where the answer can be checked automatically; the rest stay multiple choice (as the real app's exam mode already does)                     | The server must grade every answer; it cannot trust a self-mark                          | Low: the check itself is the real app's rule, ported in `core` |
| Shuffle randomness                   | `Math.random`                                                                                           | The injected `Random` port (same Fisher-Yates and `correct` mapping, pinned by fixtures)                                                                                    | Replayable tests and server-side control                                                 | None: the algorithm is identical                               |
| Questions per game                   | The question count is of entries                                                                        | The count is of scored items (a group part counts on its own); a group stays together, so the last one may be cut short, and its remaining parts join the tie-break reserve | Versus scores per part and the protocol counts parts                                     | Low: the real app can keep its own count                       |
| Image file names                     | The page asks for the file path                                                                         | Questions carry a random opaque name that the server maps back to the file                                                                                                  | A file name must not give an answer away                                                 | The port needs a route that serves the alias                   |
| Option index out of range            | `correct` pointing at no option gives `undefined` text and a shuffled index of -1 (pinned by a fixture) | `prepareGame` refuses the question at setup (`invalid-quiz`)                                                                                                                | A wire message cannot carry it, and it should fail before the game                       | Low: the real validator already rejects such files             |
| Choosing a game's questions          | Text and picture mix (`text-heavy`, `balanced`, ...) and an order (random, unseen, weakest)             | All entries of the chosen files are shuffled uniformly; no mix and no progress-based order. Group parts stay in order                                                       | Versus has no per-player progress; the mix is a later option                             | The port may want the mix as a host setting                    |
| Randomness strength                  | `Math.random` (single player, so predictability never mattered)                                         | The worker's `Random` must be crypto-backed: the stream fixes the positions of the correct answers                                                                          | A weak generator could be recovered from public values and used to predict later answers | The real app would need the same if it ever shares a seed      |
| Number keys 1 to 4                   | Pick an option whatever has focus                                                                       | Answer only while focus is in the question area, can be switched off with a remembered switch, not remappable. Enter and Space are unchanged                                | WCAG 2.1.4, the owner's ruling (ADR 9)                                                   | The port must decide whether to adopt the same rule            |

Add a row every time a simplification is made. Remove a row when the gap is closed.
